# Конструктор приглашений — Next.js проект

Сервис самообслуживания: любой человек заходит на сайт, выбирает шаблон,
заполняет форму — и сразу получает свою ссылку на готовую страницу
приглашения (свадьба, нахор оши, фатиха, юбилей или день рождения). Без регистрации.

Возможности: галерея шаблонов с фильтрами, экран-конверт, таймер до
события, место проведения с картой, RSVP-форма, кнопка «добавить в
календарь», фоновая музыка, **плавающие в воздухе сердца / звёзды /
конфетти / шары / пузыри**, анимации появления блоков (Framer Motion).

## Как это устроено

- **`/`** — лендинг с превью нескольких шаблонов.
- **`/templates`** — галерея всех шаблонов с фильтром по типу события.
- **`/create`** — форма создания приглашения (данные уходят в базу данных,
  файлы — в хранилище, в ответ приходит уникальная ссылка).
- **`/i/[slug]`** — страница приглашения, которую видят гости.
- **`/manage/[токен]`** — страница организатора: ответы гостей, правка, удаление.
- **`/edit/[токен]`** — редактирование приглашения (та же форма с текущими данными).

Каждое приглашение — отдельная запись в базе со своим адресом (`slug`).
Все приглашения живут на одном домене.

## Виды приглашений

Сейчас их пять, у каждого свои тексты, подписи полей, оформления и пример плана:

| Вид | Оформления | Особенности |
|---|---|---|
| Свадьба | Ботанический сад, Ночная классика, Романтика, Минимализм | пара имён через «&» |
| Нахор оши | Бирюза Самарканда, Золото шафрана | утреннее время по умолчанию (08:00), план утра |
| Фатиха | Изумруд, Жемчуг | пара имён, сдержанные торжественные цвета |
| Юбилей | Золотой юбилей, Шампань | одно имя + подзаголовок («60 лет») |
| День рождения | Конфетти, Космос, Ретро, Пастельные шары | одно имя + возраст |

Всё, чем виды отличаются друг от друга, описано в одном файле: **`lib/events.ts`**. Чтобы добавить новый
вид (например, «Сунат той»):
1. Добавьте его в `InviteType` и при необходимости новые оформления в `ThemeId` (`lib/types.ts`).
2. Опишите запись в `EVENTS` и добавьте вид в `EVENT_ORDER` (`lib/events.ts`).
3. Добавьте палитры новых оформлений в `lib/themes.ts` и орнамент в `components/Decorations.tsx`.

Галерея, форма, проверка данных и страница приглашения подхватят новый вид сами.

## Обложка («как откроется приглашение»)

Автор выбирает один из пяти вариантов. Инициалы на печати берутся из имён автоматически:

- **Конверт с печатью** — конверт с инициалами; по нажатию клапан откидывается, письмо выезжает;
- **Шторы** — занавес раздвигается и открывает приглашение;
- **Восковая печать** — большая печать с инициалами «ломается» при нажатии;
- **Простая кнопка** — минималистичная обложка;
- **Без обложки** — гость сразу видит приглашение.

Текст подсказки на конверте и печати можно заменить своим. В форме есть кнопка «Показать обложку в
предпросмотре». Музыка запускается в момент нажатия на обложку (браузеры разрешают звук только после
действия гостя); при «Без обложки» гость включает её кнопкой внизу справа.
Код: `components/Cover.tsx`, стили — в `app/globals.css` (раздел «Обложки-открытия»).
Названия обложек на экране и в базе: `envelope`, `curtains`, `seal`, `simple`, `none`.

## План мероприятия и дресс-код

- **План** — список «время, что происходит, пояснение» (до 12 пунктов). Включается галочкой; при включении
  подставляется пример для выбранного вида события, его можно править, добавлять и удалять пункты.
  Показывается красивой вертикальной шкалой (`components/Program.tsx`).
- **Дресс-код** — текст и палитра: до 6 цветов, которые гостям лучше выбрать. Готовые палитры в один клик
  или свои цвета (`components/DressCode.tsx`).

## Поддержка

- Страница **`/support`**: ответы на частые вопросы (`lib/support.ts`) и форма обращения.
  Ссылка «Нужна помощь?» есть в конструкторе, а при ошибке рядом с ней появляется «Написать в поддержку».
- Обращения сохраняются в таблице `support_tickets` и видны вам в **`/admin/support`** (пароль тот же,
  что у модерации): можно отметить «Готово» или удалить. Число новых обращений видно на странице `/admin`.
- Форма защищена так же, как создание приглашений: проверка «я не робот» и ограничение частоты.
- **Уведомления в Telegram** (по желанию): задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — и о каждом
  новом обращении вам придёт сообщение.
- Быстрые кнопки связи на `/support`: `NEXT_PUBLIC_SUPPORT_TELEGRAM`, `NEXT_PUBLIC_SUPPORT_WHATSAPP`,
  `NEXT_PUBLIC_SUPPORT_EMAIL`.
- Потерянную секретную ссылку мы намеренно не восстанавливаем: иначе любой смог бы выдать себя за
  владельца приглашения. Об этом честно сказано в ответах на вопросы.

## Защита от злоумышленников

Сайт рассчитан на публичный запуск. Защита идёт слоями; каждый слой закрывает своё.

| Угроза | Чем закрыто |
|---|---|
| Боты, массовое создание приглашений | Проверка «я не робот» (Cloudflare Turnstile) + лимит: 10 приглашений в час и 30 в сутки с одного адреса + общий предохранитель `MAX_INVITES_PER_DAY` |
| Захламление хранилища файлами | Токен на загрузку выдаётся только после проверки и не чаще 40 раз в час; жёсткие лимиты типа и размера; **ночная очистка**: файлы, на которые не ссылается ни одно приглашение, удаляются через сутки |
| Спам в ответах гостей | Лимиты по адресу и по приглашению, потолок 500 ответов на приглашение |
| Вредное или незаконное содержимое | Кнопка «Пожаловаться»; 5 жалоб от разных людей скрывают приглашение автоматически; панель `/admin` для ручной модерации |
| Подбор секретных ссылок | Токен 128 бит (перебор невозможен) + лимит на запросы управления |
| Взлом админки | Пароль на `/admin` (Basic-авторизация), без пароля админка выключена |
| Вредные данные в полях (переводы строк, чужие ссылки, неверные даты) | Строгая проверка и очистка на сервере; принимаются только https-ссылки на файлы |
| Встраивание сайта на чужие страницы, утечка секретных адресов | Заголовки безопасности (`next.config.mjs`) |

Адреса посетителей не хранятся: только хэш с секретной солью, раз в сутки журнал чистится.

### Что нужно настроить перед публичным запуском

Все переменные — в Vercel → Settings → Environment Variables (список в `.env.example`; про поддержку см. выше).

1. **`ADMIN_PASSWORD`** — длинный пароль (20+ символов). Без него `/admin` не открывается.
2. **`CRON_SECRET`** — любая длинная случайная строка. Без неё ночная очистка не работает.
3. **`RATE_LIMIT_SALT`** и **`SESSION_SECRET`** — две длинные случайные строки.
4. **Turnstile** (рекомендуется, бесплатно): на dash.cloudflare.com → Turnstile создайте виджет для вашего домена и
   вставьте `NEXT_PUBLIC_TURNSTILE_SITE_KEY` и `TURNSTILE_SECRET_KEY`. Пока ключей нет, проверка «я не робот»
   выключена, остальная защита работает.
5. Выполните весь `scripts/schema.sql` ещё раз (добавит таблицы `rate_events`, `reports`, `support_tickets` и новые колонки).
6. Сделайте Redeploy.
7. В **Vercel → Firewall** добавьте правило ограничения частоты для путей `/admin*` и `/api/*`: это защита
   на уровне сети поверх защиты в коде (в том числе от перебора пароля админки).

### Чего защита не делает

- Не распознаёт содержимое фото и видео автоматически: модерация идёт по жалобам и вручную.
  Если появятся жалобы на запрещённый контент, подключите автоматическую проверку изображений.
- Не ограничивает людей за общим адресом отдельно: в мобильных сетях несколько человек могут
  делить один IP, поэтому лимиты сделаны с запасом.
- Автоскрытие по жалобам можно использовать во вред (5 человек пожалуются на чужое приглашение):
  поэтому смотрите список в `/admin` и возвращайте ошибочно скрытые.
- Отдельной защиты от массовых DDoS-атак в коде нет: на этом уровне работает сеть Vercel.

## Ответы гостей, правка и предпросмотр

**Ответы гостей.** Форма RSVP на странице приглашения сохраняет ответ в базу
(таблица `rsvp_responses`). Организатор видит их на странице управления:
сколько человек придёт, кто отказался, комментарии. WhatsApp и почта остались
запасным вариантом — они появляются, только если сохранить ответ не удалось.

**Секретная ссылка.** После создания приглашения показываются две ссылки:
для гостей (`/i/...`) и секретная (`/manage/...`). Секретная — это и есть
«ключ» организатора: входа по паролю нет. Если потерять — восстановить
нельзя, поэтому форма просит сохранить её. Приглашения, созданные до этого
обновления, секретной ссылки не имеют, управлять ими нельзя.

**Правка и удаление.** На странице управления — кнопки «Редактировать» и
«Удалить». Ссылка для гостей при правке не меняется. Удаление стирает
приглашение вместе с ответами (загруженные фото и музыка остаются в Blob).

**Предпросмотр.** В форме создания справа — рамка телефона с приглашением,
которая обновляется по мере ввода (на телефоне — кнопка «Предпросмотр»).
Рамка — это страница `/preview`, данные в неё приходят через `postMessage`.

**Защита.** Сервер проверяет и обрезает все поля, принимает только https-ссылки
на файлы, ограничивает число ответов на одно приглашение (500).

## Фото или видео на заднем плане

В форме есть блок «Фон всей страницы»: без фона, фото или короткое видео.
Фон закреплён за экраном и остаётся на месте при прокрутке. Поверх него
лежит «вуаль» цвета темы — её плотность автор настраивает ползунком
(по умолчанию 55%), чтобы текст читался на любом фото. Блоки с плашкой
становятся полупрозрачными.

- **Видео:** MP4 или WebM до 25 МБ, лучше 5–15 секунд. Играет без звука, по
  кругу. MOV с iPhone не принимается: в Chrome и на Android он не воспроизводится
  (на iPhone в настройках камеры выберите «Наиболее совместимый» формат).
  Если у гостя включена экономия трафика или заряда, видео может не запуститься —
  тогда видна вуаль на цвете темы. При включённом «уменьшении движения» в
  системе видео не показывается вовсе.
- **Фото:** до 8 МБ. Отдельное «Фото в шапке» осталось и действует только на верх страницы.
- Лимиты и разрешённые типы файлов — в `lib/uploadLimits.ts`.
- Код: `components/BackgroundMedia.tsx`.

**Загрузка файлов.** Файлы уходят из браузера прямо в Vercel Blob, а
`/api/upload` лишь выдаёт одноразовый токен. Так обходится ограничение
Vercel в ~4,5 МБ на тело запроса к API: через обычный роут не прошли бы
ни музыка, ни видео. Понадобится переменная `BLOB_READ_WRITE_TOKEN`
(создаётся при подключении Blob к проекту).

## Плавающие анимации

В форме создания есть блок «Плавающая анимация»: сердца, звёзды, конфетти,
воздушные шары, пузыри или без анимации. Выбранные элементы плавно парят
по всей странице приглашения после открытия конверта. Для каждой темы
предлагается подходящий вариант по умолчанию (например, звёзды для
«Ночной классики», сердца для «Романтики»), но автор может выбрать любой.

Цвета частиц берутся из палитры выбранной темы, поэтому они всегда
гармонируют с оформлением. Код — в `components/FloatingParticles.tsx`.

## База данных и хранилище файлов

Без них форма создания не сможет сохранять приглашения.

1. Vercel → ваш проект → **Storage** → создайте базу **Neon** (Postgres)
   и подключите к проекту. (Prisma Postgres не подходит — у неё другой
   формат подключения.)
2. Откройте вкладку **Query** у базы и выполните **весь** файл
   `scripts/schema.sql`. Его можно запускать повторно: он создаёт таблицы
   с нуля или дополняет уже существующие (колонки `particles`, `edit_token`
   и `bg_kind`/`bg_url`/`bg_dim` для фона и таблицу `rsvp_responses`).
   После каждого обновления проекта выполняйте его ещё раз.
3. **Storage** → создайте **Blob** и подключите к проекту (для фото и музыки).
4. Проверьте в **Settings → Environment Variables**, что появилась
   переменная `POSTGRES_URL`. Если вместо неё только `DATABASE_URL` —
   везде, где есть `import { sql } from '@vercel/postgres'`, замените его на
   подключение через `createPool` с `connectionString: process.env.DATABASE_URL`.
5. Сделайте **Redeploy** (переменные применяются только к новым сборкам).

## Деплой

1. `git push` в GitHub.
2. Vercel → **New Project** → выберите репозиторий. **Application Preset —
   Next.js**, Root Directory — папка, где лежит `package.json`.
3. Подключите базу и Blob (см. выше), затем Redeploy.

## Темы и анимации

14 тем в `lib/themes.ts` (по видам событий: свадьба, нахор оши, фатиха, юбилей, день рождения). У каждой есть
палитра, шрифты, подпись стиля и `defaultParticles` — анимация по умолчанию.
Список вариантов анимаций — `particleOptions` в том же файле.

Чтобы добавить новую форму частицы (например, снежинки):
1. Добавьте значение в тип `ParticleType` в `lib/types.ts`.
2. Добавьте пункт в `particleOptions` в `lib/themes.ts`.
3. Добавьте SVG-форму и ветку в `renderShape` в `components/FloatingParticles.tsx`.
4. Добавьте значение в `PARTICLE_IDS` в `lib/validate.ts`.
